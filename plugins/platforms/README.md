# 平台与发布插件

中文 | [English](README_en.md)

`platforms/` 负责目标平台能力和把独立游戏工程变成可安装、可运行的软件包。Windows、Linux、macOS、HarmonyOS、Android、iOS 和 Web 是候选目标，不代表当前已经支持。

## 职责边界

- 平台能力：目标标识、架构、操作系统窗口与生命周期、文件路径、设备事件和工具链限制。
- 构建提供方：Rust/脚本编译、资源转换、依赖收集和目标目录生成。
- 导出器：可执行文件、应用包、安装包和符号文件。
- 发布辅助：签名、版本信息、图标、权限、清单和可复现构建。
- 验证：在目标环境运行实际产物，而不是只检查编译成功。

资源导入属于 [`assets/`](../assets/README.md)，平台相关渲染实现通过 [`rendering/`](../rendering/README.md) 的接口接入，编辑器导出按钮只属于 [`editor/`](../editor/README.md)。

## 插件划分方向

目标平台与打包格式分别命名职责。一个目标可以复用通用构建器，但平台特有行为必须由该目标插件拥有。首批实现优先完成一个桌面目标的独立项目导出，再扩展目标矩阵。

## 性能与稳定性

- 玩家包只包含选定目标和已启用插件，不包含编辑器、开发工具或其他平台二进制。
- 构建必须记录引擎版本、插件版本、资源哈希、目标、配置和依赖，支持复现与问题追踪。
- 打包过程需要路径边界、大小限制、取消和原子输出，失败不得留下看似完整的包。
- 交叉编译成功不等于平台支持；启动、渲染、输入、资源路径、升级和长时间运行分别验证。
- 签名密钥和平台凭据不得写入游戏仓库、日志或构建产物。

## 当前限制

当前仅有本机开发客户端，没有项目导出器、依赖收集、跨平台构建矩阵、签名、安装包或 HarmonyOS 支持。所有目标名称都是后续插件方向。
