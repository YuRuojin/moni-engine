# 脚本与 Agent 插件

中文 | [English](README_en.md)

`scripting/` 负责脚本语言运行时、引擎 API 绑定、agent 控制接口、调试和热重载。目标是让人和 agent 使用同一套可查询、可验证的能力描述，而不是为 agent 另建一套绕过引擎的规则。

## 职责边界

- 语言提供方：QuickJS 或其他运行时的持久实例、隔离和资源限制。
- API 绑定：版本化命令、类型声明、事件和错误结果。
- Agent 接口：能力发现、结构化调用、快照和可复现操作。
- 开发工具：断点、调用诊断、脚本重载与状态迁移。

具体游戏脚本留在游戏仓库；性能分析器属于 [`diagnostics/`](../diagnostics/README.md)，编辑器脚本面板属于 [`editor/`](../editor/README.md)。插件清单、服务定义和稳定扩展 ABI 属于 [`sdk/`](../../sdk/README.md)，本分类只拥有脚本执行与游戏自动化接口。

## 首批官方能力

保持当前每实体 QuickJS 持久宿主，并在此基础上抽离语言无关的脚本接口。TypeScript 声明、Rust 命令和协议能力描述需要同源或有一致性检查，避免 agent 读取到过期 API。

## 性能与稳定性

- 禁止每次逻辑回调重建运行时、重新编译不变脚本或无界复制实体数据。
- 脚本执行需要 CPU 时间、内存、命令、日志和结果大小限制；超限错误必须可定位到实体。
- 热重载必须定义旧状态保留、失败回滚和事件注销，不能同时保留两份回调。
- Agent 命令必须经过与本地脚本相同的验证和权限边界，不能直接写坏世界。
- QuickJS 宿主和其中的 `Rc` 状态具有线程亲和性，必须留在所属逻辑线程；其他 Rust 系统通过命令缓冲交互，不跨线程共享脚本上下文。
- 测量脚本执行与序列化成本，并区分运行时启动、单帧和长时间运行的数据。

## 当前限制

当前 QuickJS 与 NDJSON 实现在 `src/script.rs`、`src/protocol.rs`，尚未插件化。每个脚本实体使用持久上下文，顶层代码执行一次，暂停/恢复保留 JS 状态，替换脚本会重建上下文；世界快照不保存 JS 堆。断点调试、热重载状态迁移和独立权限系统仍未实现。
