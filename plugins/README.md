# 官方插件

中文 | [English](README_en.md)

`plugins/` 是官方维护能力的分类入口。这里的目录用于明确职责与依赖方向；**当前尚未实现插件清单、动态加载器、稳定 ABI 或自动发现**。第一阶段采用 Rust 静态组合，只有存在真实实现时才创建具体插件目录，不建立空壳插件。

## 分类

| 目录 | 负责 | 不负责 |
|---|---|---|
| [`rendering/`](rendering/README.md) | 渲染管线、材质、光照、阴影、后处理 | 模型文件解析、编辑器控件、平台安装包 |
| [`assets/`](assets/README.md) | 文件格式读取、导入、转换、资源元数据和缓存 | 每帧渲染决策、游戏逻辑 |
| [`gameplay/`](gameplay/README.md) | 物理、动画、音频、输入、UI、网络等运行时系统 | 引擎核心调度、平台导出 |
| [`scripting/`](scripting/README.md) | 脚本运行时、语言绑定、agent 接口、调试和热重载 | 具体游戏脚本、视觉资源导入 |
| [`editor/`](editor/README.md) | 编辑器界面、层级/检查器、场景控件和项目操作 | 玩家构建中的必要运行时 |
| [`platforms/`](platforms/README.md) | 平台能力、依赖收集、构建、导出、签名和安装包 | 材质、游戏逻辑、通用编辑控件 |
| [`diagnostics/`](diagnostics/README.md) | 性能分析、指标、日志、回放和调试视图 | 正常游戏机制或资源导入 |

一个插件只属于一个主要分类。跨分类能力通过公开接口协作，不复制对方的实现。

## DSH 式能力接缝

可替换能力按需要拆成三种角色：

- **服务定义**：消费者依赖的 Rust 数据类型和 trait。
- **服务提供方**：某种算法、格式、后端或平台的实现。
- **消费者**：使用该能力的运行时、编辑器或构建流程。

一个能力必须同时考虑三种角色，但只有角色需要独立演进时才拆包；单用途插件保持简单。消费者依赖服务定义，不直接依赖可替换提供方。新行为通过服务、类型化事件和可撤销效果注册接入，不通过修改核心循环或保存全局单例实现。

功能分类之外，一个插件可以包含 `runtime`、`editor`、`build`、`developer` 和 `test` 模块，以隔离玩家、编辑器和构建成本；模块元数据由 [`sdk/`](../sdk/README.md) 定义。运行环境不在入口硬编码插件列表，而是由 [`profiles/`](../profiles/README.md) 的有序 bundles 与补丁组合。

## 生命周期方向

[静态宿主](../sdk/plugin-lifecycle.md) 已实现注册校验、注销句柄、启动失败回滚、反向清理和有界同步任务。停用后不能留下回调、GPU 资源、线程、文件监听或后台任务。profile 发现和动态加载尚未实现，必需能力加载失败必须明确报告。

首阶段优先静态注册，避免不稳定的 Rust 动态库 ABI 和热路径跨进程成本。未来的原生动态插件需要显式信任与版本检查；不可信导入器或工具优先隔离在独立进程中，不能因崩溃带走编辑器或玩家运行时。

## 官方、第三方与游戏专属插件

- 本目录只放官方维护插件。
- 第三方通用插件使用独立仓库和版本化发布，不复制进引擎源码。
- 游戏专属插件由游戏仓库管理，通过项目配置引用。
- 插件兼容性由引擎版本、接口版本和目标平台共同决定，不能只看插件名称。

## 性能与稳定性要求

- 未启用插件不得产生每帧 CPU/GPU 工作，也不得进入玩家构建。
- 热路径插件需要声明分配、CPU/GPU、内存和加载成本，并提供代表性测量。
- 异步任务必须有所有者、取消路径和结果上限，禁止无界队列。
- 插件错误不得破坏世界快照或留下半完成注册。
- 可选功能默认关闭时，核心行为、快照和性能应保持不变。

## 新增插件的文档要求

具体插件放在 `plugins/<分类>/<插件名>/`，并同时提供 `README.md` 和 `README_en.md`。实现出现后，其 README 至少说明用途、公开接口、依赖、配置、生命周期、性能成本、平台限制和验证方式。分类 README 只维护职责和直接插件索引，详细接口归属具体插件。
