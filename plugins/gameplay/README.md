# 游戏系统插件

中文 | [English](README_en.md)

`gameplay/` 负责可复用的运行时游戏机制，包括物理、动画、音频、输入、游戏 UI、网络、寻路和其他有明确所有者的系统。具体游戏的角色、关卡和战斗逻辑留在独立游戏仓库，不进入官方插件。

## 职责边界

- 物理：碰撞形状、刚体、查询、步进和确定性要求。
- 动画：剪辑、状态、混合、骨骼和事件轨道。
- 音频与输入：可替换运行时提供方、资源生命周期、动作映射和高层设备状态；操作系统原始事件由 [`platforms/`](../platforms/README.md) 适配。
- 游戏 UI 与网络：运行时界面、会话、同步和消息限制。
- 通用机制：通过核心命令和组件接口读写世界，不直接修改内部存储。

纹理和模型解析属于 [`assets/`](../assets/README.md)，视觉效果属于 [`rendering/`](../rendering/README.md)，编辑器中的系统面板属于 [`editor/`](../editor/README.md)，构建目标属于 [`platforms/`](../platforms/README.md)。

## 首批官方能力

优先定义组件数据、系统执行顺序和固定逻辑帧接口，再选择输入、物理或动画中的单一垂直切片。每个系统独立可选，不能为了加入一个机制把所有后端变成核心必需依赖。

## 性能与稳定性

- 系统顺序、时间步长和所有权必须明确；渲染帧率不能改变确定性模拟结果。
- 物理追帧、网络消息、音频回调和实体事件必须有时间、数量或内存上限。
- 大规模实体查询应按数据布局测量缓存和分配成本，避免每帧复制整个世界。
- 网络与设备回调不能无界阻塞逻辑线程；异步结果需要取消和过期处理。
- 停用系统时必须注销输入、音频、物理和网络资源，且不影响其他系统。

## 当前限制

当前只有基础实体、变换、模型、脚本命令和固定逻辑帧，没有物理、动画、音频、正式输入组件、游戏 UI、寻路或网络系统。
