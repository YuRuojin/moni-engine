# Scene editor plugin

[中文](README.md) | English

`mod.rs`, `document.rs`, `project.rs`, `scripts.rs`, `ui.rs`, `ui_egui.rs`, and `viewport.rs` implement the scene editor behind the `editor` command. At startup the composition root resolves the project context (see "Project mode" below) and hands the merged profile to the editor session; the composition root installs the QuickJS runtime when building the editor session — script components stay inert data outside play mode and execute with the simulation ticks during play.

## Project mode

- Project detection: `moni editor` run in a directory containing `game.mngp` adopts that project; `--project PATH` opens a project from another directory and switches the process working directory **globally** to the project root — from then on every workspace-relative path (documents, assets, scripts, saves) resolves inside it. Running inside the project directory needs no chdir. The editor offers no `--profile` override; the project's declared profile is always the base.
- Profile merge: the project's patches/config apply first, the editor then force-enables its own tool plugins (`core.render`, `core.editor`, `core.simulation`, `core.fbx`, overriding project patches that disable them), and a render config patch is appended last (`collectGpuTimestamps` and `hotReload`; keys merge with later keys winning). Detection and merge live in the composition root's `resolve_editor_launch` (`src/main.rs`) with unit tests.
- Default scene: the project's main scene (the `scene` field of `game.mngp`); `--scene` still overrides the default. Without a project the editor stays in workspace mode (`editor` profile + benchmark scene).
- Project panel (`ui_egui.rs`): shows the current project's name/profile/root (or "no project — workspace mode"); "Open project..." (path input) and "New project..." (runs `moni new <path>` as a child process through `project.rs::spawn_new_project`, reusing the cook importer's timeout/status pattern) open projects; the recent list persists under the user config directory `%APPDATA%` (Windows) / `$HOME` (unix) → `.moni/editor-recent.json` (bounded at 10 entries, deduplicated by path and moved to the front). The open flow verifies `game.mngp` and the main scene file, chdirs, and rebuilds the document state through the guarded `open_scene` path (history, selection, and dirty anchor reset); only fully successful opens are recorded.
- A successful project open triggers one automatic TypeScript build (see "Scripts panel"); auto-builds only run in interactive sessions, not in `--frames` automation runs.

## Panels

- Play toolbar: Play / Pause / Resume / Stop buttons, a PLAYING/PAUSED state indicator, and the current tick; Space toggles between play and stop.
- Hierarchy panel: entity list (id + name) selection, create, per-entity delete and rename.
- Inspector: name, Transform (drag values applied on change-commit), attached dynamic components driven by the registered schema (number ranges, enum combo boxes, color/path/string text inputs, object JSON), component add (value pre-filled from schema defaults) and remove; replacing a component re-attaches a new value.
- Undo/redo (Ctrl+Z / Ctrl+Y and depth-labeled buttons), dirty indicator, save (Ctrl+S), and save-as.
- Asset browser: a flat categorized listing of the workspace's scenes (`.mnsc`), models (`.fbx`/`.mnec`), and scripts (`.js`/`.ts`), descending at most 3 directory levels with a 500-entry cap, skipping `target/`, `node_modules/`, `.git/`, and `examples/dist/`; the listing is cached per session revision (no re-walk during play) with a Refresh button forcing a re-walk. Scene entries offer Open, model entries Spawn (creates an entity with an FBX component; cooked `.mnec` sources pass `Model3d` validation exactly like `.fbx`), and script entries offer Attach to selected (reads the file contents onto the selected entity, with a size check before the read; the engine's `script_too_large` guard stays authoritative).
- Scripts panel (`scripts.rs`): the Build button runs `npm run build -- --pretty false` in the project/workspace root (`npm.cmd` on Windows); stdout+stderr are captured on worker threads so the UI never blocks, with a 120-second timeout killing a hung build. Output is parsed into a structured diagnostic list `{file, line, col, code, message}` (lenient `path(line,col): error TSxxxx: message` matching, non-matching lines ignored); each diagnostic that has an entity whose script source references the file offers Locate (bidirectional path-suffix match against `ScriptState.source_path`/path-shaped inline source, lowest matching entity id wins, calls `document.select` — files are never attached to entities), and ownerless errors stay non-clickable. The panel also shows a bounded raw output tail (4000 characters, line-aligned). A failed build is non-fatal; the engine reads and validates path-form scripts at scene load (`scene::load_script`), so a failed build also blocks scene loading with "could not read scene script" — the panel's status explains that connection.

## Viewport editing

- Viewport interaction runs in the free central area between the panels (`ui_egui.rs::show_viewport`, at the `Panels::show` panel seam). The scene fills the whole window behind the panels, so 3D projection uses the egui screen size (matrix conventions mirror the wgpu renderer's `view_projection` exactly), while the sprite layer maps through the renderer's `world.viewport` pixel space — sprites are drawn by `shader.wgsl` in pixel space without the camera, and picking and the gizmo mirror that fact. The pure math lives in `viewport.rs` (projection round-trips, picking, snap quantization, camera operations): no render dependency, deterministic f32/f64 math, unit-tested.
- Click-select: a left click in the viewport selects the entity under the pointer through `viewport.rs::pick_entity`; empty space clears the selection. Selection is document state, so the hierarchy panel follows automatically. Sprites resolve by the renderer's `(layer, id)` draw order (topmost hit wins; sprites draw last with no depth and beat models); 3D models take the nearest ray hit — cubes/planes use axis-aligned boxes (an AABB approximation ignoring rotation) and fbx models of unknown bounds use a unit sphere at the transform position.
- Move gizmo: with exactly one entity selected the editor draws three colored axis arrows (X red, Y green, Z blue); screen-space hit-testing (14-point radius) grabs a handle. Dragging converts the pointer delta into movement along the axis (models scale by the projected axis segment's pixel length, sprites use sprite-space deltas directly), quantized by the snap step (default 0.25; the toolbar Snap toggle and step input; snapping off quantizes to whole units at step 1.0). Sprite entities expose only X/Y (the engine 2D transform has no z, committed via `SetTransform`); model entities expose all three axes (committed via `SetModelTransform`; rotation/scale untouched).
- Drag commit semantics: while dragging, every frame previews through `EditorDocument::preview_apply` — history is untouched, revision and dirty bookkeeping advance as usual; on release, a changed final transform records exactly one "move entity" history entry through `EditorDocument::record_external_edit` (whose undo restores the drag-start transform), while a drag ending where it started restores exactly and records nothing. A drag whose entity is deleted or undone midway ends silently with no commit.
- Renderer grid: enabled once on the first UI frame through `RenderPluginApi::set_grid_visible(true)` and toggled from the toolbar Grid checkbox; golden mode never creates the UI, so by construction golden captures never touch the grid flag and stay byte-deterministic.
- Mouse camera operations: right-drag orbits around `camera.target` (radius preserved, pitch clamped below the pole), middle-drag pans in the camera plane (grab convention: content follows the pointer), applied through `Command::SetCamera` exactly like the keyboard camera path; a gizmo drag owns the pointer exclusively and never orbits the camera at the same time.

## Unsaved changes and exit

- While the document is dirty (live revision past the save anchor) and not playing: the window close button and Esc raise a Save / Discard / Cancel confirmation modal (a plain egui window). Save runs `document.save()` first; a failed save keeps the window open with the error surfaced. Only Discard, a successful save, or a clean document actually exits. Closing while playing exits directly (play state is transient and unsavable by design).
- Scene switches attempted while dirty (asset browser Open, opening a project from the panels) go through the same modal first, then proceed or abort; during play, scene switches are still refused by the document's play lock.

## Render and edit pipeline

- Open and validate `.mnsc`. The scene is opened through the `EditorDocument` in `document.rs`: undo/redo history, selection, and dirty tracking are document state, and every edit goes through the session command API, producing the same revisions and events as agent edits.
- Display FBX/cooked scenes with the same rendering and asset providers; move the camera with arrows (yielding to egui while it owns the keyboard), zoom with PageUp/PageDown, reset with Home, and orbit/pan with right/middle mouse drags (see "Viewport editing").
- Show entity hierarchy, model resources, materials, lights, and performance overlays; overlay quads are rebuilt only when the input signature changes, timings are quantized to 0.1 ms, and golden mode always installs an empty overlay. The character overlay stays the diagnostics display, separate from the egui panels; its scene path follows the document, so scene and project switches are reflected.
- Play mode (`document.rs`): `enter_play` captures the pre-play world and starts `core.simulation`; `exit_play` stops the provider and restores the pre-play world through `Engine::load_world` — the revision moves forward and `WorldLoaded` is emitted (deliberately not `EngineSnapshot`, which would roll the revision backward), and the document is conservatively marked dirty after the restore. While playing, `apply`, every convenience edit, undo/redo, and save/save-as refuse explicitly (the classic play-mode editing lock); redraw frames drive the same fixed-step accumulator as the windowed client (at most 5 ticks per frame, through `RuntimeSession::step` and the plugin host); a simulation failure exits play mode with the error surfaced on the panel error line instead of crashing the app. Script hosts are cleared by `load_world` and rebuilt fresh on the next play (script heap state is never snapshotted).
- The edited frame reaches the render plugin through the type-erased `RenderPluginApi::set_egui_frame` (payload `(Vec<egui::ClippedPrimitive>, egui::TexturesDelta, f32)`: egui 0.37 tessellation must run on the context that produced the shapes, so the editor tessellates before the hand-off; contract documented in `crates/moni-core/src/host.rs`), and the wgpu side composites it with egui-wgpu as the last layer before present.
- Golden mode fully disables egui (no egui context is created, no frame is sent, and no auto-build runs), keeping golden captures byte-deterministic; golden mode also ignores the play shortcut.
- `Panels::show` ends with the viewport interaction (picking, gizmo, grid toggle, mouse camera ops), driving the same document API; future viewport tools plug into the same spot.

## Limitations

No docking, animations, control registration, or plugin UI SDK. Scripts can only be replaced, never removed — the core command set has no script-removal command, so undoing a first attach keeps the script. The asset browser is a flat list without thumbnails, drag-and-drop, or a directory tree. Component field widgets are driven by schema property types; there is no hand-written per-component UI. The diagnostic Locate mapping matches source paths by suffix only: entities referencing built output (such as the template scene's `build/main.js`) do not claim errors from `.ts` source files. Viewport editing currently ships the move gizmo only: rotate/scale gizmos are not implemented, and picking uses approximations (rotation-ignored AABBs for cubes/planes, a unit sphere for fbx, sprite rotation ignored); sprite space coincides with egui coordinates at the default 960x540 surface and scales proportionally after a window resize. The core stays egui-free; egui types appear only in this directory and the render plugin.
