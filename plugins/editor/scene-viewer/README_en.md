# Scene editor plugin

[中文](README.md) | English

`mod.rs`, `document.rs`, `ui.rs`, and `ui_egui.rs` implement the scene editor behind the `editor` command. The `editor` profile mounts `core.simulation` (registered, not started), `core.render`, `core.fbx`, and `core.editor`; the composition root installs the QuickJS runtime when building the editor session — script components stay inert data outside play mode and execute with the simulation ticks during play.

## Current capabilities

- Open and validate `.mnsc`. The scene is opened through the `EditorDocument` in `document.rs`: undo/redo history, selection, and dirty tracking are document state, and every edit goes through the session command API, producing the same revisions and events as agent edits.
- Display FBX/cooked scenes with the same rendering and asset providers.
- Show entity hierarchy, model resources, materials, lights, and performance overlays; overlay quads are rebuilt only when the input signature changes, timings are quantized to 0.1 ms, and golden mode always installs an empty overlay. The character overlay stays the diagnostics display, separate from the egui panels; its scene path follows the document, so scene switches made through the asset browser are reflected.
- egui editing panels (`ui_egui.rs`, pinned to egui 0.37 + egui-winit 0.37 in this directory's Cargo.toml):
  - Hierarchy panel: entity list (id + name) selection, create, per-entity delete and rename.
  - Inspector: name, Transform (drag values applied on change-commit), attached dynamic components driven by the registered schema (number ranges, enum combo boxes, color/path/string text inputs, object JSON), component add (value pre-filled from schema defaults) and remove; replacing a component re-attaches a new value.
  - Undo/redo (Ctrl+Z / Ctrl+Y and depth-labeled buttons), dirty indicator, save (Ctrl+S), and save-as.
  - Play toolbar: Play / Pause / Resume / Stop buttons, a PLAYING/PAUSED state indicator, and the current tick; Space toggles between play and stop.
  - Asset browser: a flat categorized listing of the workspace's scenes (`.mnsc`), models (`.fbx`/`.mnec`), and scripts (`.js`/`.ts`), descending at most 3 directory levels with a 500-entry cap, skipping `target/`, `node_modules/`, `.git/`, and `examples/dist/`; the listing is cached per session revision (no re-walk during play) with a Refresh button forcing a re-walk. Scene entries offer Open, model entries Spawn (creates an entity with an FBX component; cooked `.mnec` sources pass `Model3d` validation exactly like `.fbx`), and script entries offer Attach to selected (reads the file contents onto the selected entity, with a size check before the read; the engine's `script_too_large` guard stays authoritative).
  - Rejected edits (revision conflict, future version, schema validation) surface as a panel error line without clearing selection or history.
- Play mode (`document.rs`): `enter_play` captures the pre-play world and starts `core.simulation`; `exit_play` stops the provider and restores the pre-play world through `Engine::load_world` — the revision moves forward and `WorldLoaded` is emitted (deliberately not `EngineSnapshot`, which would roll the revision backward), and the document is conservatively marked dirty after the restore. While playing, `apply`, every convenience edit, undo/redo, and save/save-as refuse explicitly (the classic play-mode editing lock); redraw frames drive the same fixed-step accumulator as the windowed client (at most 5 ticks per frame, through `RuntimeSession::step` and the plugin host); a simulation failure exits play mode with the error surfaced on the panel error line instead of crashing the app. Script hosts are cleared by `load_world` and rebuilt fresh on the next play (script heap state is never snapshotted). Scripts execute alongside simulation ticks during play (the QuickJS runtime is installed by the composition root); exiting play clears script hosts via `load_world` and they are rebuilt on the next play.
- The edited frame reaches the render plugin through the type-erased `RenderPluginApi::set_egui_frame` (payload `(Vec<egui::ClippedPrimitive>, egui::TexturesDelta, f32)`: egui 0.37 tessellation must run on the context that produced the shapes, so the editor tessellates before the hand-off; contract documented in `crates/moni-core/src/host.rs`), and the wgpu side composites it with egui-wgpu as the last layer before present.
- Golden mode fully disables egui (no egui context is created and no frame is sent), keeping golden captures byte-deterministic; golden mode also ignores the play shortcut.
- Move the camera with arrows (yielding to egui while it owns the keyboard), zoom with PageUp/PageDown, and reset with Home.

## Limitations

No docking, animations, project editing, control registration, or plugin UI SDK. Scripts can only be replaced, never removed — the core command set has no script-removal command, so undoing a first attach keeps the script. The asset browser is a flat list without thumbnails, drag-and-drop, or a directory tree. Component field widgets are driven by schema property types; there is no hand-written per-component UI. The core stays egui-free; egui types appear only in this directory and the render plugin.
