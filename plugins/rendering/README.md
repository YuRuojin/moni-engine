# 渲染插件

中文 | [English](README_en.md)

`rendering/` 负责把场景数据转换为画面，包括可替换渲染管线、材质、光照、阴影、后处理和渲染调试所需的视觉扩展。当前 wgpu 渲染实现位于 [`wgpu/`](wgpu/README.md)（`mod.rs` 与 WGSL 着色器），已随官方插件目录组织，但仍以 `#[path]` 静态编译进主 crate，动态加载与稳定 ABI 尚未实现。

## 职责边界

- 渲染管线：前向、延迟或其他明确命名的管线及其 pass 组合。
- 材质：参数、纹理绑定、着色器变体、编译缓存和错误回退。
- 光照与阴影：光源类型、阴影贴图、剔除相关数据和质量档位。
- 后处理：色调映射、抗锯齿、泛光等有序屏幕效果。
- 渲染资源：网格、纹理和缓冲区的 GPU 表示；原始文件读取属于 [`assets/`](../assets/README.md)。

材质面板属于 [`editor/`](../editor/README.md)。操作系统窗口、设备能力和工具链属于 [`platforms/`](../platforms/README.md)；GPU 抽象、`wgpu` 后端、管线和着色器由本分类拥有，核心不直接实现某种渲染风格。

## 首批官方能力

优先把当前内置 2D/3D 路径抽成默认静态插件，再建立材质描述、纹理、模型和阴影的基础接口。不同风格应通过数据与可替换管线实现，避免在核心着色器中堆叠互斥条件。

## 性能与稳定性

- 网格、纹理、采样器、管线和缓冲区必须复用，禁止无界每帧创建。
- 需要测量 CPU 提交时间、GPU pass 时间、绘制调用、三角形数量、显存和着色器编译卡顿。
- 材质变体与缓存必须有上限和失效规则；异步编译不能阻塞逻辑帧。
- 避免同步 GPU 回读。窗口缩放、设备丢失和插件停用必须释放或重建正确资源。
- 可选阴影或后处理关闭时，不应保留其 render pass、纹理和每帧计算。

## 实现

- [`wgpu/`](wgpu/README.md)：当前 2D/3D/阴影渲染提供方及 WGSL 着色器。

## 当前限制

已支持外部 FBX 网格、材质基础色/金属度/粗糙度、方向光、最多 8 个点光源、1024 阴影贴图与 3x3 PCF、GPU 顶点缓存、模型矩阵和包围球视锥剔除。没有完整纹理材质、级联阴影、后处理或实例化。已有 CPU 与主/阴影 pass GPU 基线，但没有多场景矩阵或显存基线。
