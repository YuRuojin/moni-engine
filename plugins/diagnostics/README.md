# 诊断插件

中文 | [English](README_en.md)

`diagnostics/` 负责观察引擎而不改变游戏语义，包括性能分析、CPU/GPU 指标、结构化日志、内存与资源计数、确定性回放采集和调试视图。这里提供运行时测量提供方；固定场景的基准执行与回归验收属于 [`testing/`](../../testing/README.md)。

## 职责边界

- 性能采集：逻辑帧、渲染提交、GPU pass、脚本和资源导入的耗时。
- 稳定性数据：分配、内存、句柄、任务队列、错误和资源释放。
- 回放与对比：固定输入、场景、版本和环境下的重复测量。
- 调试展示：覆盖层、轨迹和导出报告；编辑器面板通过 [`editor/`](../editor/README.md) 接入。

诊断插件不改变物理结果、资源内容或打包规则；这些行为归属对应分类。

## 首批官方能力

先提供固定场景所需的 CPU 帧时间、内存和脚本计时采集，再由 [`testing/`](../../testing/README.md) 运行基准和判断回归，随后增加 GPU 时间戳。诊断数据保留原始样本而不是只保留平均分。

## 性能与稳定性

- 默认关闭诊断时不得执行采样、格式化日志或分配每帧记录。
- 采样器本身要有缓冲区上限和低开销写入，避免观察者效应掩盖真实卡顿。
- 报告 p50、p95、p99、峰值、样本数、预热和环境；禁止只报告单次最快结果。
- 回放输入与快照版本必须明确，比较结果前确认场景和配置一致。
- 长任务、文件导出和远程传输不能阻塞逻辑或渲染线程。

## 当前限制

`testing/` 已提供固定外部 FBX 场景的 CPU 基准，以及硬件支持时每 30 帧采样的主/阴影 pass GPU 时间戳；GPU 采样只在基准模式启用。尚未形成可插拔指标注册、回放文件、内存曲线或长时间稳定性测试，当前数据不能证明整体性能目标已经达成。
