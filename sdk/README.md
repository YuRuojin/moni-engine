# 插件 SDK

中文 | [English](README_en.md)

`sdk/` 按 dsh 的能力接缝思想定义插件契约：每项能力由**服务定义、服务提供方和消费者**组成，插件通过可撤销的服务、事件与副作用注册接入宿主。这里还维护清单、版本、权限、数据 schema 和迁移，不实现具体渲染、游戏或编辑功能。

## 职责边界

- 服务定义：消费者依赖的稳定接口；具体算法、格式、后端和平台实现作为可替换提供方。
- 生命周期：类型化事件、服务注册、效果注销和资源清理，禁止不可撤销的全局注册。
- 插件清单：标识、版本、引擎/API 版本、依赖、冲突、权限和内容声明。
- 模块描述：`runtime`、`editor`、`build`、`developer`、`test` 运行域，加载阶段、平台和构建配置过滤。
- 扩展接口：组件/属性注册、系统调度、资源类型、编辑器扩展和构建步骤的公共定义。
- 兼容与迁移：插件 API、场景 schema、资源格式的版本检查和升级路径。
- Agent 可读取信息：运行时服务树、接口 schema、能力描述、权限和诊断结果，供工具与 agent 查询。

一个能力必须同时考虑定义、提供方和消费者，但只有角色需要独立演进时才拆包。消费者依赖服务定义，不直接依赖可替换提供方。

脚本语言运行时属于 [`plugins/scripting/`](../plugins/scripting/README.md)，依赖安装工具属于 [`tools/`](../tools/README.md)，有序插件组合属于 [`profiles/`](../profiles/README.md)。

## 插件包结构方向

正式实现后，每个插件包应具有清单、双语 README、变更记录、第三方许可声明、公开接口、测试和按需提供的示例与资源。代码模块按运行域隔离；内容型、脚本型、原生型和混合型插件使用同一套身份与依赖规则。

首阶段只提供版本对齐的 Rust 静态接口，不承诺稳定动态库 ABI。任何未来原生 ABI 都需要独立版本、目标描述和兼容测试。

## 性能与稳定性

- 公共接口需要明确所有权、调用线程、生命周期、失败语义和资源上限。
- 热路径接口避免不必要的字符串、JSON 和跨进程转换；机器可读 schema 主要用于发现、校验和工具，不应成为每帧调用格式。
- 插件注册可撤销，版本或权限不兼容时在修改世界前失败。
- schema 迁移必须可重复验证，未知插件数据不得静默丢失。

## 静态插件生命周期

[静态插件宿主与生命周期](plugin-lifecycle.md) 定义阶段、依赖、访问约束、线程亲和性、注册回滚、注销和反向清理。

## 场景格式

[Moni Scene v2](scene-format.md) 定义 `.mnsc` 的声明式相机、灯光、实体、组件和资源引用，并由 `src/scene.rs` 转换为经过校验的 `World`；v1 通过相邻迁移读取。[组件与属性 schema](component-schema.md) 统一内置组件注册、校验和 agent 描述。

## 当前限制

已有 `.mnsc` v2、v1 迁移和核心组件注册表，但没有插件清单格式、公开 SDK crate、稳定 ABI、代码生成、权限执行器或动态第三方组件注册。
