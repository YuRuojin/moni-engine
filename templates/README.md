# 游戏工程模板

中文 | [English](README_en.md)

`templates/` 负责官方维护、按引擎版本发布的独立游戏仓库模板。模板是 [`tools/`](../tools/README.md) 中项目创建命令的输入，不是引擎示例，也不要求游戏复制引擎源码。

## 模板内容方向

- 项目清单：引擎版本、插件依赖、默认 profile 和构建配置。
- Profile 声明：有序 bundles、项目插件和可覆盖的默认补丁。
- 锁文件：固定直接和间接插件版本，支持可复现安装。
- `assets/`、`scenes/`、`scripts/` 和可选的游戏专属 `plugins/`。
- 资源导入元数据、场景入口、项目说明和忽略生成缓存的版本控制配置。
- 最小可运行场景与验证命令，不包含开发机绝对路径。

引擎自身示例仍位于 [`examples/`](../examples/README.md)，profile 的组合语义位于 [`profiles/`](../profiles/README.md)，版本兼容和迁移定义依赖 [`sdk/`](../sdk/README.md)。

## 仓库边界

模板生成后，游戏仓库独立提交、分支和发布。升级引擎或插件通过项目工具和迁移完成，不直接修改引擎安装目录。通用第三方插件保持独立仓库，由项目清单引用。

## 性能与稳定性

- 最小模板默认启用少量能力，避免新项目从完整编辑器与所有游戏系统开始承担成本。
- 模板需要经过创建、安装依赖、运行、保存快照和至少一个实际导出的端到端验证。
- 缓存和构建目录可删除并重新生成；锁文件和导入元数据应纳入版本控制。
- 项目升级失败不得覆盖唯一可用的旧配置。

## 当前限制

目前没有可生成模板、项目清单规范、锁文件或 `moni new` 命令。这里只固定模板职责，尚未提供游戏工程脚手架。
